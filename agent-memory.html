Agent không nhớ — và cách GDA Kit giải quyết

AI coding agent rất giỏi trong 1 session. Nhưng session mới, nó quên sạch — lặp lỗi cũ, vi phạm rules, không biết project đang ở đâu. Bài viết này chia sẻ cách GDA Kit xử lý vấn đề này và hướng dẫn team áp dụng.

Vấn đề: Mỗi session là người mới

Context window của LLM giống bộ nhớ RAM — tắt máy là mất. Mỗi session mới, agent không nhớ:

  • Lỗi đã fix hôm qua (và sẽ mắc lại)
  • Quy tắc coding của dự án (và sẽ vi phạm)
  • Project đang ở phase nào, dùng gì, cấm gì

Ví dụ thực tế: Session 1, agent fix bug async UniTaskVoid Start() không chạy khi load scene — mất 30 phút. Session 3, gặp lại chính xác lỗi đó — lại mất 30 phút.

Tại sao "bảo nó nhớ" không hoạt động

Phản ứng đầu tiên: viết instructions "sau khi fix bug, ghi lại vào file log". Thực tế sau 10 sessions:

# Session Gotcha Captures
# Append-only

(không có entry nào)

Agent đang fix bug — context đầy stack traces, nhiều files đang edit — việc "nhớ ghi log" có độ ưu tiên rất thấp. Giống developer quên update Jira sau khi fix bug.

Nguyên tắc
Không phụ thuộc vào agent tự nhớ làm gì. Nếu quan trọng → tự động hóa. Nếu không tự động hóa được → chấp nhận mất.

Còn Native Memory thì sao?

Claude Code có MEMORY.md — native memory tự động load mỗi session. Nó hoạt động tốt cho user preferences ("respond tiếng Việt", "không tự commit"). Nhưng vẫn phụ thuộc agent tự quyết định ghi — cùng vấn đề với gotcha log. Agent có thể fix bug mà không save vào memory.

Native memory là bổ sung tốt cho preferences, nhưng không đủ cho rules enforcement hay bug prevention.

Setup guide — 3 bước, copy-paste được ngay

Không cần GDA Kit. Chỉ cần Claude Code + 3 bước dưới đây.

Bước 1: Tạo CLAUDE.md

Tạo file CLAUDE.md ở root dự án. Claude Code tự động load mỗi session.

touch CLAUDE.md
# Project: [tên dự án]

## Coding Rules
- [quy tắc 1, ví dụ: PascalCase classes, camelCase variables]
- [quy tắc 2, ví dụ: không dùng any trong TypeScript]
- [quy tắc 3, ví dụ: mỗi file < 200 dòng]

## Forbidden
- Không console.log trong production
- Không commit trực tiếp vào main
- Không thêm dependency mà chưa hỏi

## Working Style
- Respond bằng tiếng Việt
- Không tự commit khi chưa được yêu cầu
- Hỏi trước khi refactor > 3 files

Khi file vượt ~200 dòng, chia vào .claude/rules/ — Claude Code tự động inject tất cả files trong thư mục này:

mkdir -p .claude/rules
# Tách từng mục trong CLAUDE.md thành file riêng:
# .claude/rules/code-quality.md
# .claude/rules/architecture.md
# .claude/rules/testing.md
# .claude/rules/working-style.md
Cursor / Copilot

Bước 2: Tạo hooks

Hooks là scripts chạy tự động khi có sự kiện. Agent không cần làm gì.

2a. Session init — inject project context mỗi session

mkdir -p .claude/hooks
#!/usr/bin/env node
const fs = require('fs');
const { execSync } = require('child_process');

try {
  const lines = ['## Session Context'];

  // Git
  const branch = execSync('git branch --show-current', { encoding: 'utf8' }).trim();
  const status = execSync('git status --short', { encoding: 'utf8' }).trim();
  lines.push(`- Branch: ${branch}`);
  if (status) lines.push(`- Uncommitted: ${status.split('\\n').length} files`);

  // Tech stack (thêm/bớt tùy dự án)
  if (fs.existsSync('package.json')) {
    const pkg = JSON.parse(fs.readFileSync('package.json', 'utf8'));
    lines.push(`- Project: ${pkg.name || 'unknown'}`);
  }
  if (fs.existsSync('tsconfig.json')) lines.push('- TypeScript: yes');
  if (fs.existsSync('ProjectSettings/ProjectVersion.txt'))
    lines.push('- Unity project');

  // Recent fix commits — nhắc agent về bugs gần đây
  const fixes = execSync(
    'git log --oneline --since="7 days" --grep="fix"',
    { encoding: 'utf8' }
  ).trim();
  if (fixes) lines.push(`\\n## Recent fixes\\n\`\`\`\\n${fixes}\\n\`\`\``);

  process.stdout.write(JSON.stringify({ result: lines.join('\\n') }));
} catch(e) {
  // Fail-open: hook lỗi thì trả rỗng, agent vẫn chạy
  process.stdout.write(JSON.stringify({ result: '' }));
}

2b. Path guard — chặn file nhạy cảm

#!/usr/bin/env node
let input = '';
process.stdin.on('data', d => input += d);
process.stdin.on('end', () => {
  try {
    const { tool_input } = JSON.parse(input);
    const p = (tool_input?.file_path || tool_input?.command || '').toLowerCase();
    const blocked = ['.env', 'credentials', 'keystore', 'secret'];
    const hit = blocked.find(b => p.includes(b));
    if (hit) {
      process.stdout.write(JSON.stringify({
        decision: 'block',
        reason: `Blocked: path contains "${hit}"`
      }));
    }
  } catch(e) {}
});

2c. Đăng ký hooks

Thêm vào file .claude/settings.json (project-level) hoặc ~/.claude/settings.json (global):

{
  "hooks": {
    "SessionStart": [
      { "command": "node .claude/hooks/session-init.cjs", "timeout": 10000 }
    ],
    "PreToolUse": [
      { "command": "node .claude/hooks/path-guard.cjs", "timeout": 3000 }
    ]
  }
}

Bước 3: Passive bug tracking

Tự động ghi lại mỗi fix commit. Agent không cần làm gì — commit bình thường, hook tự thu thập.

#!/usr/bin/env node
const { execSync } = require('child_process');
const fs = require('fs');
const path = require('path');

// Log chung cho MỌI project trên máy (cross-project)
const logPath = path.join(process.env.HOME, '.claude', 'fix-history.log');

try {
  const log = execSync(
    'git log --oneline --since="8 hours" --grep="^fix"',
    { encoding: 'utf8' }
  ).trim();
  if (!log) process.exit(0);

  // Tránh ghi trùng
  const existing = fs.existsSync(logPath)
    ? fs.readFileSync(logPath, 'utf8') : '';
  const entries = log.split('\\n').filter(line =>
    !existing.includes(line.split(' ')[0])
  );
  if (!entries.length) process.exit(0);

  // Append
  const block = entries.map(e =>
    `[${new Date().toISOString().slice(0,10)}] ${e}`
  ).join('\\n') + '\\n';
  fs.mkdirSync(path.dirname(logPath), { recursive: true });
  fs.appendFileSync(logPath, block);
} catch(e) {}

Đăng ký — thêm vào .claude/settings.json đã tạo ở bước 2c:

"Stop": [
  { "command": "node .claude/hooks/collect-fixes.cjs", "timeout": 5000 }
]
fix-history là raw data, không tự inject
File ~/.claude/fix-history.log sẽ lớn dần theo thời gian — trở thành kho kiến thức fix bug của bạn. Nhưng nó không tự động đưa vào context. Để agent thấy được, bạn cần:

• Cách 1: Thêm logic đọc file này vào session-init.cjs (lọc entries gần đây → inject vào context)
• Cách 2 (GDA Kit): Phân loại theo category, detect pattern tái diễn, promote thành gotcha — xem bài chi tiết

Còn Native Memory?

Claude Code có native memory (MEMORY.md) — tự động load mỗi session. Nó xử lý tốt user preferences (ngôn ngữ, working style). Để Claude Code tự quản, không cần setup gì. 3 bước trên giải quyết phần mà native memory không cover: rules enforcement, project state detection, bug tracking.

GDA Kit làm gì thêm?

GDA Kit mở rộng 3 lớp trên cho domain Unity game dev:

  • 14 rule files chuyên về Unity: MonoBehaviour limits, assembly deps, SO-first, ScratchCard gotchas
  • session-init detect Unity version, URP, MCP provider, gate status, recent skill gotchas
  • Gotcha system đầy đủ: category inference, recurring pattern promotion (≥2 sessions), distribute vào từng skill, upstream về Kit repo cho cross-device
  • Conditional rules inject: edit file nào → gợi ý reference doc liên quan

Nhưng 3 lớp cơ bản ở Part 2 là nền tảng — áp dụng được cho bất kỳ dự án nào.

Tại sao không inject gotcha trực tiếp vào context?

Chúng tôi đã thử 2 cách và cả 2 đều không phù hợp:

  • Inject tất cả gotchas lúc session start: 53 files = ~14,000 dòng. Không khả thi về token.
  • Hardcode gotcha vào hook: match keyword → inject 1 dòng. Hoạt động tốt, nhưng mỗi gotcha mới phải sửa code hook → không scale.

Cách hiện tại — session-init nhắc tên skill có gotchas mới, agent tự đọc file — đơn giản và scale tốt. Agent đã có tool Read để đọc bất kỳ file nào, vấn đề chỉ là nó cần biết đọc file nào — và session-init giải quyết đúng việc đó.

Còn RAG?
RAG (Retrieval-Augmented Generation) — query chỉ lấy đúng phần cần thay vì load tất cả — nghe hợp lý cho bài toán này. Nhưng với quy mô hiện tại (12 categories, session-init nhắc tên), chưa cần. Agent đã có tool đọc file, chỉ cần biết đọc file nào. RAG đáng cân nhắc khi gotchas scale lên 100+ categories hoặc cần semantic search ("code này có thể gây memory leak" → match gotcha về pooling dù không có keyword trùng).
Agent không có trí nhớ, nhưng môi trường có thể. Thay vì mong agent nhớ — xây hệ thống để môi trường nhắc.
