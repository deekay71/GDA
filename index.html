Part 1

AI Agent là cái quái gì?

Không phải chatbot fancy đâu nha. Khác hoàn toàn luôn.

Quên hết mấy cái chatbot đi

Mọi người cứ nghe "AI agent" là nghĩ ChatGPT phiên bản xịn hơn. Nope. Khác hoàn toàn nhé.

Chatbot giống kiểu bạn hỏi ông đi đường: "Quán phở đâu anh?" — "Rẽ trái 200m." Xong. Ổng đi mất, bạn tự lội.

Agent giống kiểu bạn gọi Grab: chỉ cần nói "đến quán phở Thìn". Ổng tự bật GPS, tự chọn đường, kẹt xe ổng tự vòng, tới nơi ổng bấm chuông. Bạn chỉ việc ngồi lướt TikTok.

Nói ngắn: chatbot = Google Maps text. Agent = Grab tự lái.

Agentic Loop — Bên trong não agent

OK vậy agent "thông minh" kiểu gì? Thật ra cơ chế đơn giản lắm:

3 bước. Lặp đi lặp lại. Task đơn giản = 5 vòng. Build game = 500 vòng.

6 vòng. Mỗi vòng nó tự quyết dựa trên kết quả vòng trước. Không ai bảo nó "nhớ check compile đấy" — nó tự biết. Cái hay nhất: agent tự quyết chạy bao nhiêu vòng. Đó gọi là agency — quyền tự quyết.

Khoan, ngon vậy thì thả nó chạy free luôn đi?

Haha ĐỪNG. Chuyện thật 100%: session đầu tiên, thả agent chạy tự do. Nó refactor architecture 6 lần trong 3.5 tiếng. 64% thời gian vứt thùng rác. Chạy như gà mất đầu luôn.

Agent muốn chạy tốt cần 5 thứ:

5 thứ agent cần: Tools, Context, Memory, Guardrails, Human Oversight. GDA cung cấp cả 5.

Phổ agent: Từ "noob" đến "pro"

GDA đang ở Level 3-4. Mỗi battle-test session nó lại level up thêm xíu. Vẽ voi thì ai cũng giỏi — cái khó là biến con voi thành code chạy được.

Tại sao game dev cần agent?

Setup lặp: Mỗi game mới = tạo project, folders, packages, scenes, base scripts, assembly defs... Mình làm mất nửa ngày. Agent: 1 session.

Boilerplate: ServiceLocator, EventBus, ObjectPool, SceneLoader — project nào cũng giống nhau. Agent copy-paste thông minh.

Testing hell: Build xong mới test = tìm bug muộn. Agent test sau mỗi edit. Bug bắt sớm = fix rẻ.

Consistency: Dev A viết MonoBehaviour 300 dòng, dev B viết 50 dòng. Agent: luôn < 150 dòng vì rules bắt mỗi turn.

Knowledge giữ lại: Wiki team — ai viết? Ai đọc? Ai update? Gotchas.md — agent đọc MỖI LẦN, auto-updated.

Tất nhiên agent KHÔNG thay được: game design sáng tạo, art direction, "cái feel khi chơi", business decisions. Mấy cái đó vẫn là việc của bạn. Agent chỉ chạy sau khi bạn đã biết mình muốn gì.

Claude Code — Cái nền để chơi

Nó không "nói về code". Nó gõ code vào project luôn.

Claude Code ≠ Claude Chat — Đừng nhầm

Claude Code là CLI tool chạy trong terminal. Nó có quyền đọc/ghi file, chạy bash, và — cái này mới sốc — thao tác Unity Editor thật. Khi bạn gõ claude trong terminal, nó detect project, đọc CLAUDE.md, load rules, khởi tạo hooks, chờ bạn ra lệnh.

CLAUDE.md — JD cho nhân viên AI

File thần thánh nhất. Nằm ở root project, Claude Code auto-đọc mỗi session. Bạn viết gì trong đây, agent nghe theo đó. Nói cách khác: bạn "lập trình" agent bằng tiếng Việt. Không Python, không framework, không boilerplate.

CLAUDE.md của GDA ~200 dòng: project context, mandatory first steps, skill map, approval gates, agent roles, scene architecture. Session 1 hay session 100, agent mở lên đều đọc → biết mình là ai, biết workflow, biết limit.

Rules — Biển báo cắm mỗi 500m

Thư mục .claude/rules/ chứa mấy file .md được inject vào context MỖI TURN. Message 1 đọc. Message 200 cũng đọc. Không quên, không "trôi".

GDA có 12 rules files: language response, naming conventions, code quality, architecture enforcement, MCP wiring, gameplay testing, visual-logic alignment, ScratchCard integration, mechanic-first workflow, verification ladder, primary workflow, asset naming convention — 4 cái sau là "máu và nước mắt" từ battle-test sessions.

Hooks — Camera an ninh

Scripts tự chạy khi có event — agent không cần gọi, nó tự trigger:

  • session-init: Mở Claude Code → auto-detect Unity → load config
  • privacy-block: Đọc .env? → CHẶN. Hỏi "cho đọc không?"
  • file-size-guard: Đọc Library/? → CHẶN. Phí token.
  • naming-convention: Tạo file → check PascalCase/kebab-case ngay
  • conditional-rules-inject: Sửa code liên quan → nhắc đọc full reference
  • post-edit-compile-check: Sửa C# xong → nhắc compile

MCP — AI bấm nút Unity Editor

Nghe viễn tưởng nhưng thật 100%. Agent không chỉ viết code — nó thao tác Editor:

Skill System — Dạy AI không bị ngu

Agent "biết" ScratchCard từ training data. Kết quả: 7 bugs, 3.5 tiếng debug.

Vấn đề: "Biết" mà vẫn phá

Session đầu tiên, agent tích hợp ScratchCard package. Nó "biết" API, biết concept, tự tin lắm. Kết quả: 7 bugs. 3.5 tiếng debug. Nó không biết: gọi Init() phải chờ 5 frames (GPU chưa ready), formula progress Erase khác Restore (nhầm = game auto-complete hoặc đời đời không xong), poll GetProgress() trong Update() = lag thấy mẹ trên low-end.

Cần approach khác: chia nhỏ knowledge theo task, load đúng phần khi cần. Đó là Skill System.

GDA Architecture — Cỗ máy bên trong

Agent mù nhưng vẫn test game được. Seriously.

Identity — Không phải bot vô danh

GDA có "tính cách" ghi trong AGENT_PERSONA.md: "You are GDA, a senior Unity engineer. You NEVER ask the user to perform manual Inspector work."

5 nguyên tắc sống chết: Explicit over Magic (code đọc hiểu được), Recipe-Driven (mọi thứ trace về recipe), Logic ≠ Presentation (logic = pure C#, MonoBehaviour = thin wrapper), Fail Loud, Fix Fast (lỗi la lên, rồi tự fix), Designer-Friendly (mọi SO có [CreateAssetMenu]).

Self-Heal Loop — "Ơ lỗi à? Để tui fix"

~80% errors fix tự 1-2 vòng. ~15% fix 3-4 vòng. ~5% cần con người.

4 Approval Gates

🔧 Không phải cứng nhắc đâu
4 gates là con số mình thấy hợp lý cho game dev. Nhưng hoàn toàn custom được — thêm gate giữa Sprint 3 nếu game phức tạp, bớt gate nếu prototype nhanh, đổi nội dung mỗi gate tùy thể loại. GDA là framework, không phải luật. Bạn sửa file gate-specs.md là xong — agent sẽ follow theo cấu hình mới ngay lập tức.

Gameplay Testing — Mù mà vẫn test

Plot twist: agent không nhìn thấy màn hình. Test bằng gì? Structured logs.

[PLAYTEST][ACTION] Drag at (3,5) — tool: sponge, size: 0.5
[PLAYTEST][RESULT] ScratchCard progress: 0% → 45%
[PLAYTEST][STATE]  Step 2 — Cleaning (chưa xong)
[PLAYTEST][ERROR]  Expected progress > 0 but got 0!!!

Mechanic-First — 1 cái 1 lần, lock rồi next

TapToRemove  → test → lock ✓  (15 phút)  ★☆☆☆☆
TapToAdd     → test → lock ✓  (15 phút)  ★★☆☆☆
DragToTarget → test → lock ✓  (20 phút)  ★★★☆☆
DragToErase  → test → lock ✓  (30 phút)  ★★★★☆

1.5h cho 5 mechanics — vs 3.5h debug khi code cùng lúc

Verification Ladder — 4 tầng test bottom-up

~10-14 gates thay vì 110 naive. Giảm 90% test surface.

Đập đi xây lại — Bài học thật

Toàn là máu và nước mắt. Nhưng đau rồi mới khôn.

"Biết" mà vẫn sai — Session đau nhất

Agent tích hợp ScratchCard. Tự tin: "Biết rồi, API quen mà!" → 7 bugs. 3.5 tiếng debug. Gần cả buổi chiều.

#BugAgent "biết" nhưng...
1OnProgress fire 0%GPU cần 5 frames sau Init()
2Step auto-completeNhầm formula Erase/Restore
3BrushSize=0 crashShader divide by zero
4ScratchCard tự InitStart() race condition
5Poll trong UpdateLow-end lag
6Quên Clear()Texture cũ hiện ma
7Init lúc click toolPhải init lúc load step

Fix: bắt buộc đọc SKILL.md + gotchas trước khi code. Session #2: 0 bugs cũ. Session #4: 0 bugs.

Bài học: LLM "biết" ≠ "biết đúng cho project bạn". Knowledge > Intelligence. Quan trọng là ghi lại — dẫm 1 lần thì là tai nạn, dẫm 2 lần thì là ngu.

Agent "thay bồ" 6 lần — Refactor Guard

Session 2/4/2026: Agent refactor architecture 6 lần trong 3.5h. SO → Prefab → Hybrid → Independent → Prefab → Per-step Controller. 64% thời gian vứt sọt rác.

Fix: MAX 2 pivots/session. Pivot #3 → STOP, hỏi sếp 3 options. Có spike protocol nữa — trước khi refactor > 3 files phải tạo prototype trong Test scene, verify xong mới áp vào production. Nếu coi bug là anh zai tồi, thì việc yêu lại zai tồi là không chấp nhận được :((

Rules Injection — Biển báo mỗi 500m

Không injection: Message 1 nhớ rules. Message 200 quên. Có injection (12 files, ~400 lines/turn): quality đều như vắt chanh dù 200+ messages. Token cost nhỏ, ROI cực khủng.

Gotchas = Vaccine

Mỗi gotcha = +1 immunity. Compound, vĩnh viễn, không diminishing returns.

Roadmap

Phase 1 (đang làm): Puzzle games — match-3, ASMR, bubble shooter, 2048. 47 skills (cả standalone) đủ ship game thật.

Phase 2: Mở rộng genre — idle, runner, tower defense. Infra reuse 100%, chỉ thêm skills.

Long-term: GDA Kit — Clone → Config → Go. Bất kỳ Unity project nào. Giống create-react-app nhưng cho agent dev.

Upgrade agent không cần model mới

Insight quan trọng nhất cả series: agent khôn hơn nhờ knowledge engineering, không phải model mới.

  1. Viết skill mới → agent biết thêm task type
  2. Thêm gotchas → +1 immunity, compound, vĩnh viễn
  3. Viết rule mới → enforce mãi mãi mỗi turn
  4. Thêm hook → prevention > cure
  5. Cải thiện verification → catch more bugs

Muốn thử? Bắt đầu từ đây

Level 1 — Đọc hiểu (30 phút): Gọi ly trà đá, đọc CLAUDE.md, 2-3 SKILL.md, lướt SKILL_ROUTER.md.

Level 2 — Ghi gotchas (mỗi session): Gặp bug → ghi Triệu chứng → Nguyên nhân → Fix → Bẫy. ROI cao nhất. Mỗi gotcha = +1 immunity vĩnh viễn.

Level 3 — Viết skill (2-4h): Dùng _SKILL_TEMPLATE_V3.md. Fill Intent, Execution, Edge cases, Red Flags. Sai thì fix — không ai đúng từ đầu.

Level 4 — Hạ tầng: Hook mới, rule mới, tối ưu router. Impact lớn nhất, cần hiểu architecture sâu.
