Gotcha v1: thiết kế tốt, thực thi thất bại

GDA Kit đã có gotcha system từ sớm. Luồng thiết kế:

  1. Agent fix bug → ghi [GOTCHA] vào log
  2. Cuối session → hook parse log → distribute vào skill docs
  3. Session sau → agent đọc skill docs → tránh lỗi cũ

Thiết kế hợp lý. Nhưng kiểm tra log sau 10 sessions:

# Session Gotcha Captures
# Append-only

(không có entry nào)

Hoàn toàn trống. Pipeline distribute chạy đều, đọc log, thấy trống, thoát. Code đúng nhưng không có input.

Bài học
Bước đầu tiên của pipeline phụ thuộc agent tự nhớ ghi → pipeline không bao giờ chạy. Agent đang fix bug, context đầy stack traces — "nhớ ghi gotcha" có độ ưu tiên rất thấp.

Nguyên tắc: passive capture

Không yêu cầu agent làm gì. Hệ thống tự thu thập từ git commits.

  1. Passive capture: scan git log — agent không cần thực hiện hành động bổ sung
  2. Pattern detection: chỉ promote khi lỗi xuất hiện ≥2 sessions — 1 lần chưa phải pattern
  3. Cross-project: log chung trên thiết bị, không phụ thuộc project

3 tầng

Mỗi tầng lọc chặt hơn. Raw data → recurring patterns → shared knowledge.

Tầng 1: Git scan tự động

Cuối session, hook scan git log --since="8h" tìm commits có prefix fix/bugfix/hotfix. Tự infer category từ commit message. Ghi vào file chung:

[FIX] date: 2026-04-29
[FIX] project: MyGame
[FIX] commit: abc123
[FIX] error: fix: async Start() not firing in scene load
[FIX] category: async-lifecycle

File nằm ở ~/.claude/gda/ — ngoài mọi project. Mọi project trên cùng máy ghi chung → cross-project.

Tầng 2: Pattern promotion

Group fixes theo category, đếm distinct sessions. Cùng category ≥2 sessions = recurring pattern → auto-promote thành [GOTCHA].

Tầng 3: Distribute + Upstream

Promoted gotchas được ghi vào evolution/gotchas.md của skill tương ứng. session-init hook surface gotchas mới cập nhật cho session sau. Gotchas universal (multi-project) push về Kit repo qua git.

Category — key của pattern matching

Hệ thống nhận diện pattern bằng category tag. Cùng category xuất hiện ở 2+ sessions = recurring.

async-lifecycle      — async Start/Awake, UniTaskVoid pitfalls
null-ref-wiring      — SerializeField unassigned
scratchcard-init     — 5-frame delay, Erase/Restore formula
destroy-parent       — Destroy(transform.parent.gameObject)
event-handler-async  — Async in EventBus = silent failure
ddol-setactive       — DDOL + SetActive(false) = lifecycle dead
find-in-update       — GetComponent/Find in Update
so-runtime-write     — Writing to ScriptableObject at runtime

Category tự động infer từ commit message khi agent không ghi:

function inferCategory(message, files) {
  const m = (message + ' ' + files).toLowerCase();
  if (/async|unitask|lifecycle/.test(m)) return 'async-lifecycle';
  if (/null.*ref|serialize|wiring/.test(m)) return 'null-ref-wiring';
  if (/scratch.*card|scratchcard/.test(m)) return 'scratchcard-init';
  if (/destroy|parent.*gameobject/.test(m)) return 'destroy-parent';
  // ... 12 patterns
  return 'uncategorized';
}

Luồng hoạt động thực tế

Project A, Session 1:
  Agent fix async Start() → git commit "fix: async Start()"
  Cuối session → hook scan git → ghi fix-history.log
  Category: async-lifecycle. Lần đầu → chưa promote.

Project B, Session 5:
  Agent fix async Start() (project khác, cùng lỗi)
  Cuối session → fix-history.log có async-lifecycle ở 2 sessions
  → AUTO-PROMOTE thành [GOTCHA]
  → Distribute vào skill gotchas.md

Project C, Session 1:
  session-init surface gotcha "async-lifecycle"
  Agent dùng void Start() + InitAsync().Forget() ngay
  → 0 lỗi liên quan.

Edge cases

  • Trùng commit: kiểm tra hash trong fix-history → không ghi trùng
  • Đã promote: kiểm tra category trong session-gotchas.log → không promote 2 lần
  • Thư mục chưa tồn tại: tự tạo ~/.claude/gda/
  • Stop hook bị ngắt: /gda-end là lớp bảo vệ thủ công

Áp dụng cho dự án không dùng GDA Kit

Phần cơ bản (scan git + ghi log) chỉ cần 1 hook ~30 dòng. Xem code mẫu collect-fixes.cjs trong bài Agent Memory — copy-paste được ngay.

GDA Kit mở rộng thêm: category inference, pattern promotion (≥2 sessions), distribute vào skill docs, upstream về Kit repo. Những phần này cần thiết khi dự án lớn, nhiều skills, nhiều projects.

Lỗi gặp 1 lần = ghi nhận. Lỗi lặp lại = promote thành gotcha. Gotcha = kinh nghiệm vĩnh viễn.
